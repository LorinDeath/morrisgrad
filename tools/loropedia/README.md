# Лоропедия — импорт летописи из Obsidian

Лоропедия (`/loropedia`) собирается **при сборке** из заметок хранилища Obsidian «Летопись». БД нет: импорт
кладёт всё в статичные файлы, а Astro-страницы читают их на этапе сборки.

## Как обновить

```bash
nice -n 10 node tools/loropedia/import.mjs [путь_к_хранилищу] [--report /tmp/loropedia-report.json]
nice -n 10 npm run build
```

* По умолчанию хранилище берётся из `/workspace/obsidian_letopis` (`DEFAULT_VAULT` в `config.mjs`).
* Отчёт (`--report`) — что исключено, что вычищено и почему. **Кладите его вне репозитория**: там служебные
  названия, которые не должны попасть на сайт.

## Что создаётся

| Файл | Что внутри |
| --- | --- |
| `src/data/loropedia/data.json` | статьи (HTML), категории, теги, связи, хронология, галерея, статистика |
| `public/loropedia/search.json` | компактный индекс поиска: название, прозвища (`aliases`), теги, выдержка, статус |
| `public/loropedia/img/*` | арты, сжатые в webp (полный размер + превью) и jpg-фолбэк для соцсетей |

## Что делает импорт

* YAML-фронтматтер → инфобокс (тип, статус, клан, роль, «также известен как», арт).
* `[[вики-ссылки]]` → ссылки на статьи; ссылка на ненаписанную/скрытую статью → пометка «статья не написана».
* Dataview-запросы → обычные таблицы/списки, посчитанные во время импорта.
* `status` из фронтматтера → плашки «✅ Канон», «💡 Не канон / идея», «⚠️ Спорно», «📎 Справка»;
  `invented: true` → плашка «Додумано» (фильтруется как «не канон»).
* Обратные ссылки («Упоминается в») и граф для карты связей.

## Скрытые темы (`config.mjs`)

* `HIDDEN_TERMS` — регулярка тем, которые **не публикуются**. Заметка с такой темой в названии исключается
  целиком; абзацы/строки с ней в тексте вырезаются.
* `MIN_KEEP_RATIO` — если после вырезания осталось меньше этой доли текста, заметка исключается
  (кроме типов из `KEEP_ALWAYS_TYPES`).
* `EXCLUDE_NOTES`, `EXCLUDE_IMAGES` — ручные исключения (служебные заметки, «Идеи Алекса», отдельные арты).
* Поле `источник` из фронтматтера в инфобокс не выводится.
* `HEADING_RENAMES`, `TEXT_REPLACEMENTS` — точечные правки формулировок при импорте.

Импорт в конце сам проверяет, что скрытые термины не попали в `data.json` и `search.json`, и падает, если попали.

## Локальный просмотр

`astro preview` идёт через Clerk-middleware, ему нужен `CLERK_SECRET_KEY`. Для локального просмотра положите
`.dev.vars` (в git не попадает) в `dist/server/` **после каждой сборки**:

```bash
cp .dev.vars dist/server/.dev.vars && nice -n 10 npx astro preview --port 4417
```
