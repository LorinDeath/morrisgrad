# Проход безопасности и производительности (октябрь 2026)

## Найдено и исправлено
1. **Выбивание чужой сессии по userId (DoS).** `join` выбивал прежние сокеты по `u:<msg.userId>`, но userId в join не проверен (токен Clerk проверяется позже). Любой мог выбить игрока, зная его id.
   Исправлено: до проверки ключ берётся только по guestId; выбивание по аккаунту идёт в `meta.onVerified` по проверенному uid. Непроверенный `msg.userId` больше не пишется в `session.userId` (вне dev).
2. **Dev-доверие (`MC_DEV_TRUST_USERID`)**: проверено, что флага нет в `server/wrangler.json` (там нет ни vars, ни env), а `.dev.vars` в репозитории отсутствует. Флаг задаётся только через `wrangler dev --var`.
   Защита в глубину: dev-режим (userId без токена, `dev_teleport`, `dev_spawn_mob`, `dev_plant_flower`, `dev_grant`) теперь требует флаг **и** подключение к localhost/127.0.0.1 (`isDevRequest`, флаг хранится в `session.dev`). Флаг, случайно включённый в проде, на публичном домене ничего не включит.
3. **Лимиты для всех сообщений** (`server/limits.ts`). Размер ≤ 64 КБ проверяется до `JSON.parse`, бинарные сообщения отбрасываются. На каждый сокет — токен-бакет: в среднем 60/с, всплеск до 120. После 200 подряд отброшенных сообщений сокет закрывается (1008). Сообщение должно быть объектом со строковым `type` ≤ 40 символов.
   Ник в join: только строка, не длиннее 32 символов (раньше нестроковый ник бросал исключение).
4. **Роли**: кэш `player_roles` перечитывается раз в минуту, так что снятие роли в D1 доходит без перезапуска DO. Админ-сообщения проверяют `roles.isAdmin(ms)` по проверенному uid, а поля `userId`/`role` в сообщении игнорируются (плейтест admin.js). Попытки без роли пишутся в журнал.
5. **SQL**: все запросы D1 и DO-SQL используют `?`-плейсхолдеры. Единственная динамическая часть — список `?` в `IN (...)` (rating.ts). Конкатенации пользовательских значений нет.
6. **Валидация админ-правок**: разрешены только поля схемы, числа проверяются на диапазон, `__proto__` и чужие id отвергаются, черт не больше 6, шанс 0…100. Квесты: id `c_…`, ограниченная длина.
7. **Серверная авторитетность**: позиция ограничена по скорости в открытых мирах; урон, черты, лут и разведка считаются на сервере; клиент присылает только намерения.

## Производительность (бенчмарк зоны Аринара, 3217 мобов)
| игроков | update, мс/тик (бюджет 50) | state, мс/игрок | размер state |
|---|---|---|---|
| 1 | 0.54 | 0.025 | ~430 Б |
| 20 | 1.84 | 0.008 | ~490 Б |
| 60 | 2.62 | 0.009 | ~480 Б |
Спящие чанки работают: при 60 игроках бодрствуют 395 мобов. Узких мест не найдено.

## Тесты
`server/meta/security-test.ts`: 27 проверок (конфиг, dev-хост, флуд/размер, валидация, черты). Плейтесты admin/social/duel/rating/arinar проходят.

## Известные ограничения
- Правки админки другие клиенты получают при переподключении. Сервер подхватывает их по версии раз в 10 с.
